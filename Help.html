1. Requisitos e instalação

  • Python 3.11 ou superior (testado com 3.11.4).
  • Pacotes obrigatórios: numpy, pandas, scipy, plotly, matplotlib, streamlit, typer, PyYAML — instalados automaticamente.
  • Pacotes opcionais: numba (backend cpu acelerado), cupy / pyopencl (apenas detecção de GPU — não são backends de execução, ver § 8).

Instalação a partir do clone (recomendado)

git clone https://github.com/ileaof/combustionpy-double-wiebe.git
cd combustionpy-double-wiebe
python -m venv .venv
.venv\Scripts\Activate.ps1          # Windows (PowerShell)
python -m pip install --upgrade pip
pip install -e .                    # instala o pacote + o comando `double-wiebe`

Extras opcionais:

pip install -e ".[cpu]"     # numba: RK4 em lote compilado (backend cpu)
pip install -e ".[dev]"     # pytest
pip install -e ".[cuda]"    # cupy: APENAS detecção de GPU em `devices`/GUI
pip install -e ".[opencl]"  # pyopencl: APENAS detecção de dispositivos
Nota: os extras [cuda] e [opencl] não aceleram a calibração — CUDA/OpenCL não são backends de execução deste pacote (justificativa em docs/hpc.md). O caminho de aceleração real é o backend cpu (numba), § 8.

Verificar a instalação

double-wiebe --help          # lista os comandos
double-wiebe validate        # caso de referência: RMSE 412,658 kPa / R² 0,930841
double-wiebe devices         # CPU, numba, CUDA, OpenCL e backends disponíveis

3. Início rápido

Simulação de referência (dados de exemplo)

double-wiebe simulate --data data/example_pressure.txt `
    --config configs/example.yaml --output outputs/run_01

Escreve em outputs/run_01/: results.csv, parameters.yaml, metrics.json, gráficos e report.html — § 10.

Calibração

double-wiebe calibrate --data data/example_pressure.txt `
    --config configs/example.yaml --output outputs/calib_01 --seed 42

Por default (YAML de exemplo) calibra os 8 parâmetros livres (Rc, theta01, delta1, m1, theta02, delta2, m2, alpha) com differential evolution; ao final o melhor candidato é re-integrado com solve_ivp (o RMSE reportado é sempre do re-run serial).

GUI

double-wiebe gui          # abre o navegador em http://localhost:8501

5. Referência da linha de comando

ComandoO que faz
double-wiebe simulatesimula o modelo com os parâmetros configurados (--data --config --output --overwrite --set --quiet/--verbose)
double-wiebe calibratecalibração global + polish (--method --seed --maxiter --popsize --select Rc,m1,alpha --polish/--no-polish)
double-wiebe validatevalida config/dados contra o caso de referência
double-wiebe plotgera os gráficos estáticos de um diretório de resultado (plot outputs/run_01)
double-wiebe deviceshardware detectado (CPU, numba, CUDA, OpenCL) + backends disponíveis
double-wiebe benchmarkbenchmark reproduzível dos backends (warm-up, média, desvio, speedup; grava CSV)
double-wiebe example-configgrava/imprime o YAML de exemplo (--force para sobrescrever)
double-wiebe guiabre a GUI Streamlit (--port 8501 --headless)

Opções de desempenho do calibrate

OpçãoValores
--backendserial (referência) | cpu (RK4 em lote) | cpu-parallel (processos, bit-idêntico à serial) | auto (mini-benchmark)
--integratorauto | rk4_numpy | rk4_numba | scipy (só no backend cpu)
--workersprocessos do cpu-parallel (default: núcleos − 1)
--precisionfloat64 (default) | float32 (o resultado final é sempre re-integrado em float64)
--substepssub-passos do RK4 entre pontos experimentais (default 4)
--benchmarkmede os backends antes da calibração e grava benchmark_hpc.csv
--profileperfil cProfile da calibração

Códigos de saída

0 sucesso · 1 falha de execução · 2 erro de uso (arquivo inexistente, diretório de saída não vazio sem --overwrite, configuração inválida).

6. Interface gráfica (GUI — Streamlit)

Sete abas, todas usando o mesmo núcleo da CLI:

AbaO que faz
Experimental Dataupload do arquivo (.txt/.csv/.tsv), separador, colunas, unidades (radianos/graus; Pa/kPa/bar), filtro θ, suavização; resumo da série

Double Wiebeparâmetros das duas fases (θ₀₁/Δ₁/m₁/a₁, θ₀₂/Δ₂/m₂/a₂) e fração de energia α; modo continuous/bounded
Simulationopções do integrador e execução da simulação com os parâmetros atuais
Calibrationseleção dos parâmetros livres e limites, método (DE/PSO), seed/iterações e o expander Desempenho (backend/integrador/workers/precisão/sub-passos + painel "Hardware detectado"); executa com Start calibration, com barra de progresso (thread separada)
ResultsRMSE/R², indicadores (pico de pressão, T máx, fração queimada, calores), gráficos interativos (Plotly) e o diagrama P–V

Carregar calibração: na aba Calibration, o controle 📂 Carregar calibração (.json) fica junto ao botão Start calibration — abre um arquivo salvo e restaura os parâmetros sem precisar recalibrar. Ver § 7.
Aplicar calibração: depois de calibrar (ou carregar um arquivo), o botão Aplicar parâmetros calibrados e rodar a simulação roda a simulação final com os parâmetros do resultado.

7. Salvar / abrir calibração (JSON)

  • Salvar: aba Calibration → ⬇ Salvar calibração (JSON) (aparece quando existe um resultado de calibração). O arquivo calibracao_double_wiebe.json embute: parâmetros, histórico da busca, sensibilidade, alertas, configurações de motor/Wiebe e os dados experimentais usados (θ em rad, P em kPa).
  • Abrir: aba Calibration → 📂 Carregar calibração (.json), junto ao Start calibration — disponível desde a abertura da sessão, sem precisar calibrar antes. Os parâmetros são restaurados imediatamente; os dados embutidos só são restaurados se a sessão ainda não tiver dados (nunca substitui dados carregados).
Atenção: o formato ("formato": "double-wiebe-calibracao") é próprio do projeto e não é intercambiável com o do Single Wiebe (single-wiebe-calibracao).

8. Aceleração (backends) e hardware

BackendDescrição
serialreferência — solve_ivp/DOP853 adaptativo (rtol=atol 1e-9)
cpuRK4 clássico de passo fixo em lote (integrador auto: usa numba se instalado; senão NumPy). Speedup medido ≈ 38× (numba); o melhor candidato é sempre re-integrado em float64 com solve_ivp ao final (diferenca_integrador reportada)
cpu-parallela implementação serial em processos — resultados bit-idênticos à serial; compensa com populações grandes
autoescolhe o mais rápido por mini-benchmark

GPU (CUDA/OpenCL)?

Não são backends de execução — apenas detecção de hardware. Os extras .[cuda]/.[opencl] instalam cupy/pyopencl só para o comando devices e o painel "Hardware detectado" da GUI. Justificativa e benchmarks em docs/hpc.md (§2). O acelerador real do pacote é o backend cpu com numba.

9. Uso como biblioteca

from double_wiebe.models import load_config
from double_wiebe.data_processing import read_table, prepare_series
from double_wiebe.simulation import run_simulation

cfg = load_config("configs/example.yaml")
dfr = read_table("data/example_pressure.txt")
theta, P, resumo = prepare_series(
    dfr, angle_unit="radianos", pressure_unit="bar",
    theta_min=-2.0, theta_max=2.0)
res = run_simulation(theta, P, cfg["engine"], cfg["wiebe"], cfg["simulation"])
print(res.metrics["RMSE_kPa"], res.metrics["R2"])

from double_wiebe.calibration import run_calibration, CalibrationConfig
calib = CalibrationConfig(method="differential-evolution",
                          selected=["Rc", "m1", "alpha"], seed=42)
resultado = run_calibration(theta, P, cfg["engine"], cfg["wiebe"],
                            cfg["simulation"], calib)

Todas as exportações ficam em double_wiebe.reporting (results_csv_bytes, metrics_json_bytes, static_plots, report_html_bytes, export_all etc.).

12. Solução de problemas

SintomaCausa e solução
double-wiebe não é reconhecidoambiente virtual não ativado ou pacote não instalado — repita pip install -e . dentro do .venv
“esperado um arquivo salvo pela GUI” ao abrir JSONarquivo de outro projeto (formato single-wiebe-calibracao) ou truncado — os formatos dos dois projetos não são intercambiáveis
CUDA: indisponível no painel/devicesnormal sem cupy — e não acelera nada de qualquer forma (ver § 8); instale .[cuda] só para a detecção exibir a GPU
calibração lenta na serialuse --backend cpu (com .[cpu]) ou --backend auto; instale numba para o melhor ganho
relatório HTML sem figurasnão deve ocorrer — o botão gera as figuras na hora; se ocorrer, gere os PNGs com double-wiebe plot outputs/run_01 ou reabra a GUI
GUI congela durante a calibraçãoa busca roda em thread separada com progresso; aguarde — o polling re-renderiza a cada ~1 s; Cancel calibration encerra entre iterações
pressões com valores deslocadosconfira a unidade (data.pressure_unit) e a coluna (data.pressure_col) — o exemplo usa bar
